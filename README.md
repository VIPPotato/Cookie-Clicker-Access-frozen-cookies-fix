# Cookie Clicker Access (Frozen Cookies compatibility fork)

Cookie Clicker Access makes the game playable with a screen reader. It adds ARIA labels, keyboard
navigation, a heading structure and spoken announcements to the game's interface, and it covers the
minigames as well as the main screen. NVDA, JAWS, Narrator and VoiceOver all work with it.

This README describes version 15.0. The mod runs on the Steam build of Cookie Clicker and on the web version through Tampermonkey.

This fork exists because of one specific defect: with the upstream mod loaded, Golden Cookies could
not be clicked at all while Frozen Cookies was running. That is fixed here. The full list of
differences is under "What this fork changes".

## How the code was written

All code in this mod is generated by AI (Claude). Direction, design decisions and QA testing are
done by human players. No part of the code was written by a human developer.

## Install on Steam

Subscribe on the Steam Workshop:
[Screen Reader Accessibility Enhancements](https://steamcommunity.com/sharedfiles/filedetails/?id=3807399658)

Steam downloads it and the game picks it up on the next launch. Open Options, then Mods, and check
that **Screen Reader Accessibility Enhancements** is enabled. Version 15.0 announces
"Screen Reader Accessibility mod version 15.0 loaded." when it starts. The Workshop item and GitHub downloads are updated separately, so check the announced version after installing.

### Remove the older accessibility mod first

Do this before you launch the game with the Workshop version installed.

Version 14.0 changed the mod's internal ID from `nvda accessibility` to
`screen reader accessibility`. The game treats a new ID as a different mod, so an older copy is not
replaced or upgraded. Both load, both label the same elements, and every heading and announcement is
read twice.

Two places to check:

1. Options, then Mods. Disable or unsubscribe any other Cookie Clicker accessibility mod listed
   there, including "NVDA Accessibility Enhancements".
2. The local mods folder. Delete the folder if it exists:
   `[Steam install path]\steamapps\common\Cookie Clicker\resources\app\mods\local\Cookie-Clicker-Access\`

Restart the game after removing them. If you previously installed this mod by copying files into
`mods\local\`, the Workshop copy replaces that install, so the local folder has to go.

Old saved mod data under the previous ID is left under that ID. Version 15.0 saves no accessibility preferences and ignores older support opt-outs. Greenhouse and Frozen Cookies keep their own settings; those are separate from this mod's data. You can clear the old accessibility key under Options, Mod data.

### Manual install without the Workshop

Download `Cookie-Clicker-Access.zip` from the
[Releases page](https://github.com/VIPPotato/Cookie-Clicker-Access-frozen-cookies-fix/releases),
extract it, and copy the `Cookie-Clicker-Access` folder into:

`[Steam install path]\steamapps\common\Cookie Clicker\resources\app\mods\local\`

Use either the Workshop copy or the manual copy, not both.

## Install on the web version

1. Install the [Tampermonkey](https://www.tampermonkey.net/) extension for Chrome, Firefox, Edge or
   Safari.
2. Open
   [cookie-clicker-accessibility.user.js](https://github.com/VIPPotato/Cookie-Clicker-Access-frozen-cookies-fix/releases/latest/download/cookie-clicker-accessibility.user.js).
   Tampermonkey opens an install tab. Confirm with Install. The link always serves the script from
   the newest release.
3. Open [Cookie Clicker](https://orteil.dashnet.org/cookieclicker/). The script waits for the game to
   finish loading, then registers itself.

The userscript gives the same startup announcement as the Steam mod. To inspect registration in the browser console (F12), check that `Object.keys(Game.mods)` includes `screen reader accessibility`.

The web userscript includes base-game accessibility and the shimmer compatibility fix. It does not include the Steam-only Greenhouse or Frozen Cookies menu, shortcut and text-readout integrations described below.

## What this fork changes

This fork branches from [Cookie-Clicker-Access](https://github.com/Amsel142857/Cookie-Clicker-Access)
at version 13.8. Everything below was added here.

### Automatic support for Greenhouse and Frozen Cookies on Steam

Steam support covers Grandpa's Greenhouse 1.5 and Frozen Cookies 2.052.8, branch `erb-`. Each integration starts automatically when its supported mod is enabled, loaded and ready. There is no separate accessibility-support switch in Options. Missing, disabled or still-loading mods are left alone, without absence notices. Detection does not install either mod, enable it or change its automation settings.

The Greenhouse panel has headings, labelled automation modes and settings, breeding targets and readable layout previews. Its layout controls support choosing, creating, renaming, duplicating, deleting, importing, exporting and painting layouts with the keyboard. Tab moves through the controls; Enter or Space activates a button. Escape cancels its name/import dialogs and the layout-wipe confirmation. Native text fields, validation and confirmation still handle the actions.

Frozen Cookies has a keyboard-accessible menu button, section headings, labelled setting choices and numeric-edit prompts. Menu information stays as a snapshot while the menu is open; close and reopen it to refresh that information. Setting choices and edited values update in place.

On Steam, Frozen Cookies' native A, B, C, E, R, S and W letter shortcuts are blocked whenever the supported mod is enabled and initialized, regardless of its Shortcuts setting. Modified letters and held-key repeats are blocked too. The setting itself is left unchanged. Use the menu controls instead; ordinary text entry and Ctrl with S saving remain available.

### Frozen Cookies text readouts on Steam

Open the Frozen Cookies menu and find the Frozen Cookies text readouts heading. Infobox text lists the names and values from Frozen Cookies' own infobox output, including its Frenzy multiplier. If no output is available yet, the readout says so. Refresh infobox text reads the latest available output; it does not turn on fancy UI or force Frozen Cookies to generate new output.

Tracked stats text contains a table of recorded samples with time since run start, base CPS (cookies per second), effective CPS and earned HC (heavenly chips). The time and values use Frozen Cookies' graph formatting. Empty recordings and unavailable values are identified rather than replaced with zeroes.

The text stays unchanged until you refresh it or reopen the menu. Refresh keeps focus on its button, with the data below it, and does not announce every timer tick. It reads existing data without enabling statistics collection or automation.

View Stat Graphs also has a Tracked stats text section. Opening that native graph action still takes Frozen Cookies' own one-shot sample; the separate Refresh tracked stats text button only reads the samples already present. The graph keeps its native Close, Escape and focus-return behavior.

### Golden Cookies work with automation mods

This is the defect the fork was started for. Frozen Cookies rewrites
`Game.shimmerTypes.golden.popFunc` by stringifying it with `.toString()` and re-evaluating it with
`eval()` in the global scope. The upstream mod wrapped that same function in a closure over private
variables, so the re-evaluated copy no longer had them in scope. Clicking any Golden Cookie threw
`ReferenceError: MOD is not defined` and the click was abandoned, whether it came from Frozen
Cookies, the mouse, or a screen reader button. The cookie sat on screen until it faded.

This fork wraps `Game.shimmer.prototype.pop` instead and leaves
`Game.shimmerTypes.golden.popFunc` untouched, so Frozen Cookies can read and replace it as it
expects. Rewards are announced, cookie chain steps keep counting, and cookie storm drops are
tallied correctly on every one of those three click paths.

### Upgrade store structure

The store's upgrade section was one flat list. It now has headings so it can be navigated by heading
jumps: Special and Season Switches, Research and Tech Upgrades, Vaulted Upgrades, and Available
Upgrades with a count of what is on offer. When no standard upgrades are available, a focusable note
says so and points at the switches section above, instead of leaving an empty region with no
explanation. The Buy All button reports how many upgrades are affordable out of the total, and speaks
the names of the ones it bought.

### Seasonal drop progress

Season switch buttons report how far the season's collection has got, for example
`0/7 heart biscuits unlocked` or `14/14 Santa's gifts, 7/7 reindeer cookies unlocked`. When a season
is already running, the button reports the time left and that activating it cancels the season. The
same progress appears in the Status and Effects panel, in the season start announcement, and in the
Santa panel.

### Stats menu headings

The Stats menu had no heading structure. It now has three levels: section banners, subsection titles,
and one heading before each crate box that names the box and its item count, such as
`Achievements, 316 items`. Inline values like `Prestige level: N` stay plain text, because they are
values rather than section titles.

### Milk readout

The milk flavour in the stats readout follows the Milk selector, matching what the game draws and
what the big cookie's label says. It previously always reported the achievement rank flavour, so the
two readouts contradicted each other. During a Born again ascension it falls back to the rank
flavour, because the game ignores the selector in that state. Rank and percentage stay
achievement-based.

### Pantheon spirit placement

Placement is verified before it is announced. The mod reads the slot back after the attempt, so a
failed placement no longer reports success and no longer spends a worship swap. Activating a spirit's
own slot now says it is already there, rather than reporting the slot as occupied. An error thrown
inside the game's placement call is reported instead of disappearing.

### Dialogs and prompts

The game's own prompts rebuild their markup from scratch every time you pick an option, which
discarded the labels the mod had applied. The dragon aura picker and the challenge mode picker both
went silent and lost keyboard access after the first keypress. Both are now relabelled on every
rebuild, they announce what you selected, and focus stays on the option you picked instead of jumping
back to the dialog title. Aura and mode names come from the game's localized names, so a translated
game is no longer described in English. Aura crates say whether an aura is the one equipped in that
slot or a pending choice that still needs Confirm.

The permanent upgrade slot picker announces how many upgrades are on offer and moves focus to the
first crate, without pulling focus back to the top of the list after each selection.

### Quieter announcements during dialogs

Background announcements are held back while a modal dialog is open, so the game does not talk over a
prompt you are reading. Urgent events still speak: shimmers, wrinklers, veil breaks and achievements.
Dialogs keep their own voice, including the save confirmation and slot selection feedback.

### Renamed for all screen readers

The mod is called Screen Reader Accessibility Enhancements. The old name named only NVDA, although
the mod has always worked with JAWS, Narrator and VoiceOver too. The internal ID changed with it, as
described under "Remove the older accessibility mod first". Any other mod that looked this one up
through `Game.mods['nvda accessibility']` needs updating to `Game.mods['screen reader accessibility']`.

### Automated tests

The repository carries a test harness at `tests/harness.js`, which upstream does not have. See
"Running the tests".

## Mod compatibility

- **[Frozen Cookies fork](https://steamcommunity.com/sharedfiles/filedetails/?id=2816199538):** the shimmer compatibility fix remains in both distributions. Steam also has automatic menu, shortcut and text-readout support for version 2.052.8, branch `erb-`.
- **[Grandpa's Greenhouse](https://steamcommunity.com/sharedfiles/filedetails/?id=3792850996):** Steam has automatic panel and layout accessibility for version 1.5. The integration leaves its automation settings and native actions in charge.
- **Cookie Garden Helper Reloaded:** automatic planting, harvesting and soil rotation run without
  disturbing the garden grid's arrow key navigation.
- **CCSE (Cookie Clicker Script Extender):** supported as a mod loader.
- **Cookie Assistant:** runs alongside with no known conflicts.

Frozen Cookies' experimental 100% Consistency Combo is off by default. If enabled, its Garden stage can harvest the plot and request Whiskerbloom planting without consulting Greenhouse's layout or clearing confirmation. Frozen Cookies also harvests the Garden as part of its reset route. Cookie Clicker Access does not coordinate or disable either mod's automation and does not prevent this conflict.

Load order matters when two mods wrap the same game function. If something behaves oddly after
installing, check the order in Options, Mods. A newly installed mod is added at the bottom of the
list.

## Navigating by heading

The interface is divided into sections with real HTML headings. Use your screen reader's heading key,
such as H in NVDA's browse mode, to move between them.

- News (level 2). The game's news ticker. Focusable, with live announcements turned off so it does
  not interrupt.
- Store (level 2). Contains Special and Season Switches, Research and Tech Upgrades, Vaulted
  Upgrades, Available Upgrades, and Buildings, each at level 3.
- Wrinklers (level 2). Active wrinklers, with buttons to check swallowed cookies and pop them.
- Status and Effects (level 2). Dragon level and auras, Santa, the active season and its drop
  progress, Grandmapocalypse stage, Elder Pledge, Golden Switch, Shimmering Veil, and active buffs
  with their countdowns.
- Shimmers (level 2). Golden Cookies, Wrath Cookies and Reindeer currently on screen, with the time
  left on each.

## What the mod does

### The big cookie

The big cookie has a label and can be clicked with your screen reader's activation key or the mouse.
Text readouts for Cookies per Click and milk progress sit below it.

### Upgrades

Upgrades are labelled with their name, cost and effect. Unaffordable ones carry an estimate of how
long until you can afford them. Special and season switches are grouped separately from standard
upgrades, so the seasonal switches do not get lost among them.

### Buildings

Each building reports its name, whether you can afford it, the current cost for your bulk buy setting
(1, 10, 100 or Max) and how many you own. An info line below each one carries the production details.
Buildings you have not unlocked yet are hidden, apart from the next one and one unknown entry, which
keeps the list short.

### Ascending

The Legacy button reports the prestige level and heavenly chips you would gain. On the ascension
screen, heavenly upgrades carry their name, cost and whether you own them. Permanent upgrade slots
open a dialog you browse with the up and down arrows, choosing with Enter or leaving with Escape.

## Minigames

A minigame unlocks when its building reaches level 1 with a sugar lump. Each one has an accessible
open and close button, and Escape closes any open minigame panel.

### Garden (Farm)

The garden grid is a real grid you move through with the arrow keys in NVDA's focus mode. Focus it
below the Plots heading. Each tile reports its plant, growth percentage, harvest readiness and its
row and column. Enter or Space plants your selected seed on an empty tile, or harvests a mature
plant. Tab reaches the seed and soil selectors. A separate button harvests only fully mature plants,
which leaves growing parents and mutations alone.

### Grimoire (Wizard Tower)

The magic bar reports current and maximum magic and the number of spells cast. Each spell reports its
cost, whether you can cast it, what it does and its backfire chance.

### Pantheon (Temple)

The Diamond, Ruby and Jade slots report their occupant or that they are empty. Each spirit lists its
title, its effect in each slot tier, and has a button per slot. Swap count and cooldown are read out
as well.

### Stock market (Bank)

Each stock reports its name and ticker, shares owned, price and trend, in that order. Buy and sell
buttons carry the stock symbol and the quantity.

## Game mechanics with extra handling

- **Shimmers:** a Golden Cookie, Wrath Cookie or Reindeer appearing triggers an interrupting
  announcement, and a warning fires 10 seconds before it fades. The Shimmers panel holds a button per
  shimmer with its countdown. During cookie chains and cookie storms the per cookie chatter is
  suppressed and only the start, step count and final total are announced.
- **Wrinklers:** new wrinklers are announced. Each has a button that reports its swallowed cookies,
  if you own Eye of the wrinkler, and pops it.
- **Sugar lumps:** announcements cover the lump type (normal, bifurcated, golden, meaty,
  caramelized), whether it is ready to harvest, and your lump total.
- **Krumblor and Santa:** both menus are accessible for levelling, petting and picking dragon auras.

## Keyboard

- H, and Shift with H, in browse mode: next and previous section heading.
- Arrow keys in the garden grid, in focus mode: move between plots.
- Enter or Space on a focused element: activate a button, buy a building or upgrade, plant or
  harvest.
- Escape: close minigames, the dragon and Santa menus, selectors and dialogs.
- Ctrl with S: save the game, which announces "Game saved."

## Building the userscript

The Steam mod is `main.js`, loaded directly. The web version needs a bundled userscript, built from
`main.js` and `userscript-header.txt`:

```bash
chmod +x build-userscript.sh
./build-userscript.sh
```

The script writes `cookie-clicker-accessibility.user.js`, ready to import into Tampermonkey. It removes the Steam-only optional-mod integrations from the web bundle while retaining the base-game shimmer compatibility fix. Steam testing does not need this step.

## Running the tests

`tests/harness.js` builds a small fake DOM and `Game` object, loads the real `main.js`, captures
announcements instead of speaking them, and exercises the logic directly. Run it from the repository
root:

```bash
node tests/harness.js
```

Point it at another copy with the `CC_MAIN` environment variable to compare behaviour:

```bash
CC_MAIN=/path/to/other/main.js node tests/harness.js
```

The harness checks the logic, not the screen reader experience.
